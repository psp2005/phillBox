화면 전환은 어떻게 일어나는가

복약기 프로젝트 · useState 방식과 react-router · 2026-09-12

1. 지금은 이렇게 화면이 바뀝니다

주소는 하나도 안 바뀝니다. 실제 코드로 보겠습니다.

상태 하나가 "지금 어느 화면인지"를 기억합니다

const [screen, setScreen] = useState('login')      // App.jsx:47

그 값에 따라 다른 컴포넌트를 그립니다

if (screen === 'login')      { return <LoginPage ... /> }           // 70번 줄
if (screen === 'register')   { return <DeviceRegisterPage ... /> }  // 144번 줄
if (screen === 'device')     { return <DeviceDetailPage ... /> }    // 160번 줄
if (screen === 'medication') { ... }                                // 176번 줄

버튼을 누르면 그 값을 바꿉니다

onAddDevice={() => setScreen('register')}         // 119번 줄
onOpenMedication={() => setScreen('medication')}  // 168번 줄
onBack={() => setScreen('devices')}               // 170번 줄

일어나는 일을 순서대로

① [+ 등록] 클릭
      ↓
② setScreen('register')
      ↓
③ 리액트가 "상태가 바뀌었네" 하고 App 을 다시 그림
      ↓
④ if (screen === 'register') 가 참이 됨
      ↓
⑤ <DeviceRegisterPage /> 가 그려짐

브라우저는 아무것도 모릅니다. 주소창은 그대로고, 히스토리에도 아무것도 안 쌓입니다.

비유 — 화이트보드 한 장에 그림을 지우고 다시 그리는 것과 같습니다. 방을 옮긴 게 아니라 같은 자리에서 내용만 바꾼 거죠. 그래서 "뒤로"라는 개념 자체가 없습니다.

2. react-router — 라이브러리가 맞습니다

npm 패키지입니다. express 나 pg 처럼 남이 만들어둔 코드 뭉치예요.

하는 일은 딱 두 가지입니다.

① 주소를 바꾼다 (그리고 히스토리에 쌓는다)
② 지금 주소에 맞는 컴포넌트를 그린다

②는 지금 if (screen === ...) 가 하던 일과 같습니다. 판단 기준이 screen 상태에서 주소로 바뀔 뿐이에요.

3. 브라우저 기능을 빌려오는 것이 맞습니다

브라우저가 원래 갖고 있는 것

무엇설명
주소창지금 어느 주소인지
히스토리뒤로·앞으로 갈 수 있는 목록

이 둘을 자바스크립트로 조작하는 표준 기능이 브라우저에 들어 있습니다. History API 라고 부릅니다.

history.pushState(null, '', '/devices')
   └─ 주소를 /devices 로 바꾸고, 히스토리에 한 칸 쌓는다

react-router 는 이걸 감싼 것입니다. 직접 써도 되지만 번거롭습니다.

pushState 의 핵심 — 서버에 안 물어봅니다

<a href="/devices">        →  서버에 새 요청  →  페이지 전체 다시 로드
                                                  → 화면 깜빡임
                                                  → 리액트 상태 전부 초기화

history.pushState(...)     →  주소만 바뀜      →  요청 없음
                                                  → 깜빡임 없음
                                                  → 상태 그대로

주소만 살짝 갈아끼우는 겁니다. 화면은 리액트가 알아서 다시 그립니다.

비유 — 호텔 방문의 호수 팻말만 바꿔 다는 것과 같습니다. 손님을 다른 방으로 옮기는 게 아니라, 같은 방의 팻말을 바꾸고 안을 다시 꾸미는 거예요. 짐(상태)을 안 옮겨도 됩니다.

이렇게 페이지를 새로 안 불러오면서 여러 화면처럼 보이게 만든 앱을 SPA(Single Page Application) 라고 부릅니다. 우리 앱이 그것입니다 — 실제 HTML 파일은 index.html 한 장뿐이에요.

뒤로가기는 브라우저가 알려줍니다

window.addEventListener('popstate', ...)
   └─ 사용자가 뒤로·앞으로를 눌렀을 때 알림이 옴

react-router 가 이걸 듣고 있다가 주소에 맞는 컴포넌트로 바꿔 그립니다.

그래서 안드로이드 뒤로가기가 동작합니다 — 하드웨어 버튼이든 화면 제스처든, 결국 브라우저의 "뒤로"를 부르고, 그게 popstate 로 전달됩니다.

4. 정리 — 무엇이 바뀌나

지금 라우터 이후
화면을 정하는 것 screen 상태 주소
화면을 바꾸는 것 setScreen('register') navigate('/devices/new')
주소창 안 바뀜 바뀜
히스토리 안 쌓임 쌓임 → 뒤로가기 동작
새로고침하면 로그인으로 돌아감 그 화면 유지
화면 컴포넌트 7장 그대로 그대로

마지막 줄이 중요합니다. DeviceListPage · DeviceDetailPage 같은 화면 파일들은 거의 안 건드립니다. 바뀌는 건 App.jsx 하나예요 — 화면을 고르는 방식만 갈아끼우는 거니까요.

5. 미리 알아둘 함정 — 배포하면 404

주소창에 https://phill-box.vercel.app/devices 를 직접 입력
   ↓
브라우저가 Vercel 에 "devices 라는 파일 주세요" 라고 요청
   ↓
Vercel: "그런 파일 없는데요"  →  404

pushState 로 만든 주소는 브라우저 안에만 있는 가짜 주소입니다. 서버에는 그런 파일이 없어요.

언제 터지나 — 화면 안에서 버튼으로 이동할 때는 멀쩡합니다. 새로고침하거나 주소를 직접 입력할 때 진짜로 서버에 요청이 가고, 그때 404가 납니다.

해결은 한 줄입니다 — "어떤 주소로 오든 index.html 을 주라" 고 Vercel 에 알려주면 됩니다. (vercel.json 의 rewrite 설정)

작업 순서

단계할 일
1단계BrowserRouter + Routes 로 껍데기를 만든다 — 화면 1·2만 연결
2단계나머지 화면 5장을 붙인다 + useParams 로 기기 id 꺼내기
3단계하단 탭(화면 2·7)을 중첩 라우트로 정리
4단계vercel.json 으로 배포 404 막기

각 단계마다 동작을 확인하고 넘어간다. 한 번에 다 바꾸면 어디서 깨졌는지 찾기 어렵다.
